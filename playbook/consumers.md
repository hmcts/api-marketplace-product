# Consumer Guide

How to discover, request access to, and integrate with APIs published through the API Marketplace.

## What is a consumer?

A consumer is any team or service that integrates with an API product listed in the Marketplace. Consumers may be internal HMCTS teams, other government departments, or approved external partners.

## Getting started

1. **Discover** — Browse the API catalogue to find APIs relevant to your use case.
2. **Understand** — Read the API contract, documentation, and any linked recipes to understand the integration model.
3. **Request access** — Follow the onboarding instructions published by the API producer. This typically includes agreeing to data-sharing obligations and provisioning credentials.
4. **Integrate** — Build against the published contract. Use sandbox/test environments where available.
5. **Go live** — Complete any required assurance steps and move to production.

## What to expect from a well-published API

- A versioned, machine-readable contract (e.g. OpenAPI).
- Clear documentation covering authentication, error handling, and rate limits.
- Published SLAs or operational expectations.
- A named owner or support channel.
- Onboarding instructions and a test environment.

## Your responsibilities

- Integrate against the published contract — do not depend on undocumented behaviour.
- Monitor your integration and respond to deprecation or versioning notices.
- Comply with data-sharing and usage obligations agreed during onboarding.
- Report issues through the published support channel.

## Data sharing

APIs that cross organisational or partner boundaries may require a data-sharing agreement. The Marketplace provides guidance and self-service tooling to help with this. See the producer or your onboarding contact for details.

## Need help?

If you cannot find what you need in the catalogue or documentation, contact the AMp team or the named producer for the API you are interested in.
